# PrismQuant A5 指揮官智能體（Commander Agent）

> 唯一的用戶入口：把 A1 新聞情報與 A2 政要監控匯總成一份**決策級晨報**，
> 做交叉驗證、調解分歧、推演情境，並在合規護欄下交付到 Web 與 Telegram。

**A5 不是摘要器。** 摘要器回答「發生了什麼」，A5 要回答「這意味著什麼、我該盯什麼、
什麼情況下我錯了」。這三件事分別由 L0 正規化、L1 交叉驗證、L2 情境推演實現。

- 版本：v1.0.0　提示詞：`v2`　預設大腦：`lens`
- 實測（22 條新聞輸入、deepseek-chat via OpenRouter）：4,700 tokens、11–12 秒、約 US$0.0016／份
  —— 全部可在 §9.5 用同一份輸入複現，數字與核對方式逐項列出
- 依賴：FastAPI + httpx + SQLite（全部標準庫或輕量套件，`pip install` 一次搞定）
- **本 repo 只交付 A5（指揮層）**。A1–A4 由隊友負責，A5 按 §8 的契約對接；
  未接入時走降級路徑（規則層 + 內建樣本）並在頁面標明，不會把樣本當成實時數據

**v1.0.0：把「五個零件」補上（回應隊友的第二輪意見）**

隊友問的五件事，本質是「有沒有智能體底座」。這一版把五塊都做成**能真跑、能當場驗證**的東西：

| 隊友問的 | 這一版的回答 | 在哪裡看 |
|---|---|---|
| 遠端 agent 怎麼通信 | HTTP 交換 JSON 信封 + `trace_id` 貫穿 + SQLite durable log；一次 run 八步（含失敗的兩步）可回放 | `/#infra` ①、`app/bus.py` |
| 記憶怎麼管理 | 三層（工作／情景／語義）+ 同 key 合併 + 顯著性半衰 + 可刪除 + 四權重混合召回 | `/#infra` ②、`app/memory.py` |
| 工具用到了什麼 | 10 個註冊工具，帶 JSON Schema、權限級別、超時、調用審計；**禁止註冊下單工具** | `/#infra` ③、`app/tools.py` |
| 提示詞是什麼 | 六層（system/role/task/context/contract/guard）、v1→v2 版本化、可清點、防注入 | `/#infra` ④、`app/promptkit.py` |
| 有沒有 RAG 向量庫 | 有：102 份文件 / 107 塊（84 來源目錄 + 15 術語 + 3 天晨報，每跑一天 +1），餘弦 + MMR，引用標 `[K1]` | `/#infra` ⑤、`app/rag.py` |

完整推導、技術選型理由與限制見 [`docs/AGENT-INFRA.md`](docs/AGENT-INFRA.md)——那份文件可以直接發給隊友。

晨報頁也多了兩塊附錄：**引用的背景知識**（K1/K2，帶來源連結）與 **記憶延續**（上次的結論與強度）。

**v0.3 新增（接上真實大模型之後做的）**

- 大模型只寫「主線句 + 正文」，結構化章節由規則層鎖定 → 延遲由 65 秒降到約 20 秒（v0.3 當時；v1.0 的實測見 §9.5），結構永遠不會因模型抽風而壞掉。
- 生成進度串流（SSE）：看得到「取上游 → 規則層 → 大模型 → 護欄」每一步與耗時。
- **追問**：對某一份晨報繼續問，答覆必須引用證據 ID；沒 key 時退化為證據檢索並明說限制。
- **與上一份的差異**：新增／掉出的主題、方向翻轉、置信度變化——每日晨報真正的價值。
- **關注詞可在介面上改**（存在 `data/prefs.json`），改完下一次生成生效。
- 每次 run 顯示 tokens 與估算成本；一鍵匯出 Markdown。
- 歷史晨報可深連結：`/#brief/<run_id>`（Telegram 推送的連結直接打開那一份）。

**v0.8.0：明暗雙主題**

右上角新增太陽／月亮切換。整個樣式表重寫成一套**語義 token**（`--surface`、`--sunken`、
`--hairline`、`--hero-bg`…），深色與淺色只是同一組變數的兩份值——不是「反色」，是各自調過的：

- **淺色**：白底 + 髮絲線 + 柔陰影，主按鈕反轉成墨色；漲跌紅綠、置信度藍都調成淺底可讀的深色調。
- **深色**：維持原本的近黑終端風，未動。
- 選擇存在 `localStorage`，記住下次；**預設跟系統**（`prefers-color-scheme`）。
- 加 `?theme=light` 或 `?theme=dark` 可以強制某個主題（截圖、分享、演示用）。
- 切換時有 0.3 秒的柔和過渡，不硬跳。

**v0.7.0：key 可以在介面上填，每人用自己的**

不需要改 `.env`、不需要碰命令行：大腦拓撲頁最下面有「大模型連線」，貼 key → 測試 → 儲存。

- 存在本機 `data/prefs.json`（已 gitignore），**介面只回傳遮罩後的字串**（`sk-or-v…3f18`），
  前端拿不到完整 key，截圖或分享畫面都不會漏。
- 存完**即時生效**，不用重啟；重啟時 `config` 會自動載入。
- 「測試連線」會真的打一次 20 token 的請求，回報模型與延遲。
- 沒有 key 的晨報多一行提示：「到大腦拓撲貼上自己的 key →」。

**v0.6.0：它會自己上班了**

- **定時晨報**：每天 `PQ_SCHEDULE_TIME`（預設 08:30）自動生成 + 推送。
  用 asyncio 背景任務，不引入 Celery；每 30 秒檢查一次，**改 .env 不用重啟**。
  整合狀態頁有「立即執行一次」可以當場驗證。
- **A4 模擬閘門**：把晨報的傳導鏈當成假設的執行意圖，跑五條規則（方向中性→否決、
  A1/A2 未解分歧→否決、單一來源→倉位減半、置信度 < 0.50→只准觀察倉、合計 > 30%→按比例縮）。
  明確標記 simulated，不是真風控，也不是下單。這是把 proposal 的「風控否決權」演出來。
- **複製連結**：一鍵拿到 `/#brief/<run_id>`，可以直接發給人。
- **列印 / PDF 樣式**：Ctrl+P 會自動切成白底、去掉導航與按鈕，適合放進報告附錄。

**v0.5.0：介面重做（設計系統 v3）**

不是換顏色，是換結構：

- **晨報改成雙欄**：左邊是敘事（事實 → 含義 → 觀察 → 傳導 → 分歧 → 情境），
  右邊是常駐側欄（置信度表盤、資料充分性、本次執行用量），捲動時跟著走。
- **章節改成編輯體**：`01 ———— 發生了什麼 —— FACTS`，編號用等寬字，髮絲線收尾。
- **置信度從膠囊換成表盤**：64px 環形 + 30px 數字，加減分理由在下面。
- **情境加了機率條**：偏空／基準／偏多三段色彩條，先看分佈再看卡片。
- **觸發留白卡獨立成行**：A3/A4 的空位不再跟真實情境擠在同一格。
- 全站換成近黑底 + 髮絲線 + 髮絲級內陰影；主按鈕改成淺色（少數會發光的元素）。
- 資料來源改成「名稱 + 數量 + 滿寬細條」，窄欄也讀得懂。
- 鍵盤：`/` 聚焦輸入框，`⌘/Ctrl + Enter` 送出；支援瀏覽器上一頁／下一頁（hashchange）。

**v0.4.2：先讓模型判斷你想幹什麼，而不是猜關鍵詞**

之前那個框看起來像對話，但不管你打什麼都生成一份晨報——你打 `hello`，它回一份晨報。
第一版修法是寫一張關鍵詞表，結果 `你能做什麼` 命中、`你可以做什麼` 漏掉——中文的說法無窮無盡，規則永遠追不上。

現在 `commander.run()` 先問模型一次（`app/prompts/v1/router_system.md`，T=0）：

```
使用者這句話，是要一份晨報，還是只想跟你說句話？
```

- `intent = chat` → 模型**自己寫回覆**（招呼、自我介紹、能力、A5 與 A4 的分別、拒絕下單請求）。
- `intent = brief` → 進原本的流程，並把使用者的關注點壓成 `focus`，
  **相關主題會被排到最前**：問「今天港股怎樣」，主線句就是港股。
- 沒有 key、超時、JSON 壞 → 退回關鍵詞規則（不是報錯，是降級）。

模型不會亂猜狀態：連線情況與時間由系統塞進 prompt（`status_context()`），
它只負責判斷與表達，不負責編事實。

`?ask=hello` 可以直接預填並送出（示範／截圖用）。

**v0.4 新增（把「我只負責 A5」講清楚）**

- **整合狀態頁**：五個代理一覽、各自要交什麼契約、一鍵連線自檢（打真實端點、顯示原始回應）。
  這一頁是給隊友看的，不用再口頭解釋 A5 在等誰。
- **歷史記錄頁**：按日分組的時間軸、晨報／探針／追問篩選、關鍵字搜尋、**任選兩份比較**。
- **缺的部分留空，不用假數據填**：A3 未實作 → 執行意圖卡留空；A4 未接入 → 倉位含義卡留空，
  並寫明等哪個端點。晨報頂部有「這一頁用了誰的資料」覆蓋條。
- **區分「離線」與「在線但沒有資料」**：前者用內建樣本並標明；後者老實留白，
  並提示「可能未執行 /collect」——這兩件事之前被混為一談。
- 每次輸出可展開原始 JSON（驗收與除錯用）；手機窄屏版修好。

## 1. 職責邊界

| 做 | 不做 |
|---|---|
| 匯總 A1 / A2，補上來源、時間、可追溯 ID | 不抓新聞、不寫 RSS 適配器（那是 A1） |
| 交叉驗證：同一件事有幾個獨立媒體在講 | 不做爬蟲（那是 A2 的下一版） |

## 2. 三層二次分析

```
A1 新聞 ─┐
         ├─▶ L0 正規化 ─▶ L1 交叉驗證 ─▶ L2 情境推演 ─▶ 護欄 ─▶ 晨報 + 證據鏈
A2 政要 ─┘   （對齊 schema）  （數獨立來源、抓衝突）  （三情境 + 觸發/作廢條件）
```

- **L0 正規化**：A1 與 A2 的 schema 不同（`sentiment` vs `direction`、`published` vs `published_at`），
  先攤平成同一種 atom，並補上 `publisher`。A1 目前只寫 `source="RSS"`，A5 會從 URL 反推媒體名
  （BBC / Reuters / Bloomberg / 財新…），否則「來源太少」這個問題在介面上看不出來。
- **L1 交叉驗證**：按主題聚類，數「幾個獨立媒體」講同一件事。單一來源的主題會被標記並扣分；
  A1 與 A2 方向相反時產生分歧卡，並寫明**裁決規則**與**作廢條件**。
- **L2 情境推演**：由情緒分佈與驗證強度加權出基準／偏多／偏空三種路徑，附可驗證的觸發點。
  權重是可解釋的相對權重，不是價格預測。

置信度不是模型自評，是加減分規則：媒體數、A2 是否在線、衝突數、單源數、時效、樣本數據上限。
每一項都列在頁面上（「置信度」卡），可以直接被 examiner 追問。

## 3. 同一個大腦，還是不同大腦？

四種拓撲都能跑，`PQ_BRAIN_TOPOLOGY` 一個環境變數切換，介面「大腦拓撲」頁也可以即時對照。

| 拓撲 | 做法 | 什麼時候用 |
|---|---|---|
| `rule` | 不呼叫大模型 | 離線、降級、回歸測試（本專案預設降級路徑） |
| `shared` | 所有角色同一個模型、同一個溫度 | 打通鏈路、極低成本 |
| `lens` | **同一個模型 + 分角色溫度與視角（預設）** | 本專案：要一致、要可審計、要控成本 |
| `split` | 感知層快模型、指揮層強模型、風控只准規則 | 接入 A3/A4 後，或做對照實驗 |

**為什麼預設 `lens`：** A5 的價值是「可審計的解釋」，同一模型版本才能重播同一個決策；
200 訂閱者的成本上限不允許判斷層跑三次；風控不能漂移，所以 A4 根本不該配大腦。
代價是單一模型的知識盲區會貫穿全鏈，靠「交叉驗證 + 置信度扣分 + 單源降級」補償。

完整推導、成本估算與對照實驗設計見 [`docs/BRAIN-TOPOLOGY.md`](docs/BRAIN-TOPOLOGY.md)。

## 5. 快速開始

### Windows（最省事）

雙擊 `start.cmd`。第一次會自動建 `.venv`、裝依賴、開瀏覽器到 <http://127.0.0.1:8130>。
需要 Python 3.11+（沒裝會提示你去哪下載）。

### 手動

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt      # macOS/Linux: .venv/bin/pip
copy .env.example .env                             # 可選
.venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8130
```

開啟 <http://127.0.0.1:8130>。預設 8130；A1 假設在 8010、A2 在 8120，A3 由 `PQ_A3_API_URL` 指定。

### 運行狀態與頁面標記

| 狀態 | 系統行為 | 頁面怎麼標 |
|---|---|---|
| A1 + A2 已連線 | 使用它們的實時數據 | 左下角顯示「已接入」與延遲 |
| A1 或 A2 未連線 | 改用內建樣本，格式與 §8 契約一致 | 頂部紅條寫明哪個上游沒接、輸入是樣本 |
| 有 `PQ_LLM_API_KEY` | 大模型改寫主線句與正文（`lens` 拓撲） | 頂欄 `LENS`，用量與成本寫入 ledger |
| 沒有 key | 規則層直接生成，章節與證據鏈不變 | 標「已降級為規則層」 |

三條原則：

1. **降級不是「假數據開關」。** 這是 proposal §3.1 的要求：模型超時、上游失敗都要能繼續產出，
   但必須明說缺哪一塊。所以每一種降級在頁面上都有對應標記，不是靜默替換。
2. **不真假混用。** 任何一個上游失敗，整份改用樣本，而不是一半實時一半樣本——
   混用比全用樣本更危險，因為讀者分不清哪句是真的。
3. **樣本不會偽裝成實時。** 樣本條目帶 `sampled` 標記，來源欄與頂部橫幅都說明它們不是實時抓取的。

## 6. 介面

| 頁籤 | 內容 |
|---|---|
| **晨報** | 主線句、三章節（發生／意味／盯什麼）、傳導矩陣、分歧裁決、情境推演、證據鏈、資料充分性、置信度、合規聲明 |

## 8. 與 A1 / A2 / A3 / A4 的契約

四個鄰居，**三種關係**——這一點很容易被誤讀成「只要接 A1/A2」：

| 誰 | 關係 | 沒有它會怎樣 |
|---|---|---|
| A1 新聞、A2 政要 | A5 **去拉資料**（pull） | 整份改用內建示例，頁面標紅 |
| A3 執行 | A5 **去要意圖**（pull） | 不產生任何標的建議、不給倉位，執行意圖卡留白 |
| A4 風控 | A5 **把意圖交給它審**（submit） | 只有建議權（`advisory_only`），A4 的否決權不存在 |

A5 不自己扮演 A3：選哪隻標的、多少倉位、持多久，是策略與執行層的判斷（proposal Table 3）。
A5 越過這條線，整份晨報就從「可審計的研究輸出」變成「沒有風控的薦股」。

**A1**：`GET /api/v1/news/events?limit=N` → `{events:[{title, summary, sentiment, topics[], instruments[], confidence, source, url, published}]}`

**A2**（優先）：`GET /api/v1/analyses?limit=N` → `{events:[{title, summary, direction, entities[], markets[], confidence}]}`

**A2**（退化）：`GET /api/v1/public-records?order=published_desc` → 原始記錄，A5 會標記 `degraded` 並以「中性」處理。

**A3**：`GET /api/v1/intents?limit=N` → `{intents:[{instrument, direction, size_range, horizon, logic, evidence_ids[]}]}`
A5 會把它渲染進晨報的「執行意圖」卡，但**不執行**——要等 A4 放行。

**A4**：`POST /api/v1/risk/check` → `{verdict: pass|degrade|reject, limits, reasons[]}`
目前 A5 用的是本地**模擬閘門**（五條規則，標記 simulated）；A4 真接入時替換
`commander.simulate_gate()`。之所以還沒抽成適配器：A4 有否決權，接的時候要處理
「非同步裁決 / 超時怎麼辦 / 誰替使用者按下確認」，不是改一個 URL 的事。

**接入成本**：
- A1 / A2 / A3 → 改 `PQ_A1_API_URL` / `PQ_A2_API_URL` / `PQ_A3_API_URL`，**不用改程式**
- A4 → 需要替換 `simulate_gate()`（約 100 行，主要是把「本地規則」換成「遠端裁決 + 超時降級」）

兩邊都失敗才用內建樣本。任何一邊成功、另一邊失敗，仍然整份用樣本（見 §5 的三條原則）。

## 9.4 缺 A1–A4 時，A5 怎麼做

這一節是給驗收和隊友看的：A5 沒有假裝自己有完整的五代理。

| 狀態 | A5 的行為 | 介面 |
|---|---|---|
| A1 / A2 **未連線** | 整份改用內建樣本 | 紅色橫幅：「輸入是內建樣本；分析、護欄、留檔照常執行」 |
| A1 / A2 **在線但沒有資料** | 不用示例，老實留白 | 黃色提示：「已連線但沒有資料（可能未執行 /collect）」 |
| A2 只有原始記錄 | 退回退化 schema，方向記為中性 | 標記 `degraded` |
| **A3 未實作** | 不產生任何標的建議或下單意圖 | 情境區留一張「執行意圖」空卡，寫明等 `/api/v1/intents` |
| **A4 未接入** | 只有建議權（`advisory_only`） | 「倉位含義」空卡 + 頂部 A4 徽章 |
| 全部缺席 | 仍然輸出一份完整的「沒有消息」晨報 | 不會白屏 |

覆蓋條會直接寫「已接入：A5｜缺席：A1、A2、A3、A4」。

## 9.5 大模型實測（deepseek-chat via OpenRouter）

**測量條件寫在前面，否則數字沒有意義**：22 條新聞 + 9 條政要表態作為輸入、`lens` 拓撲、
`v2` 提示詞、香港時間 2026-11-16 18:48 連續跑兩次。

| 指標 | 實測值 | 怎麼自己核對 |
|---|---|---|
| 端到端延遲 | 11.6 秒 / 10.9 秒 | 頁面「本次執行」卡的 LATENCY，或 `/api/v1/runs` 的 `latency_ms` |
| 其中規則層 | 0.3–0.6 秒 | 生成進度條裡 `analyze` 階段的 `elapsed_ms` |
| 其中模型 | 約 10–11 秒 | 同一條進度裡 `llm` 階段的耗時 |
| tokens | 4,675 / 4,701（輸入 4,234 / 輸出 443） | `payload.usage`，每次 run 都寫進 ledger |
| 估算成本 | US$0.00163 / US$0.00166 | `usage.cost_usd` |
| 200 訂閱者、每日一份 | 約 US$0.33／日 | 0.00165 × 200 |
| 輸出速度 | 約 42 tok/s | 443 tokens ÷ 10.5 秒 |
| 降級 | 超時、JSON 不合契約、無 key → 自動用規則層，頁面標示 | 清空 key 或斷網跑一次 |

成本是按 `.env` 的 `PQ_PRICE_IN_PER_M=0.27` / `PQ_PRICE_OUT_PER_M=1.10` 乘出來的
（deepseek-chat 在 OpenRouter 的牌價量級）。**如果賬單跟這裡差很多，先對單價**——
`usage.cost_usd` 只是乘法，不是真實扣款。

延遲會隨網絡與模型負載浮動，擁堵時段同一份輸入可能到 20 秒以上；真正穩定的是 token 數
（4,700 上下，浮動小於 5%）。所以報告裡寫「約 4,700 tokens、十餘秒」比寫死一個秒數安全。

輸出契約只有兩個欄位 `headline` 與 `brief`。這是刻意的：讓模型寫 1000+ tokens 要 25 秒以上，
而結構化章節（發生／意味／盯什麼）由規則層產出本來就沒有幻覺。把模型的工作縮到「主線句＋正文」，
換來兩倍以上速度與永遠正確的結構。

## 11. 限制與下一步

- **A4 未接入**：所有輸出都是 `advisory_only`，不產生下單指令；這是刻意的，不是沒做完。
- **A2 目前是 RSS**：延遲高、實體粒度粗。A5 已兼容爬蟲版 schema，A2 換引擎時不用改 A5。
- **規則層的主題詞典是手工的**：新主題（例如碳關稅）會落到宏觀桶，需要補詞。這是 `evaluate` 要守的東西。
- **單篇探針的方向判斷是詞典法**：接上大模型後會補語氣與上下文；現在的分數只用於排序，不用於決策。
- **模型吞吐是硬瓶頸**：實測 deepseek-chat 經 OpenRouter 約 42 tok/s（2026-11 測），輸出 440 字要 10 秒，所以 A5 只讓它寫短文。
  若之後要它寫完整章節，得先換到更快的 provider 或加 streaming 輸出。
- **RAG 的 local 後端不是神經 embedding**：signed feature hashing + TF-IDF，512 維，
  對同義詞不敏感，換來確定性可重現。要真 embedding 設 `PQ_EMBED_BACKEND=api`。
- **消息總線是單機 SQLite**：不是 Kafka。故意如此（clone 即跑），信封格式已把傳輸層抽象掉，
  規模上去換 Redis Stream 不用改協議。
- 下一步：A3 執行意圖、A4 風控閘門、讓大模型自己選工具（`tools.specs()` 已就緒）、
  記憶權重線上學習、英文介面。
