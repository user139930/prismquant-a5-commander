# 大腦拓撲：同一個大腦，還是不同大腦？

> 這份文件回答隊友在群裡問的那句：「A5 二次分析能力如何，同埋不同 agent 係用同一個大腦好，定係不同的大腦」。
> 問題看似是術語題，其實是三個取捨：**成本、可審計、同源偏誤**。

---

## 1. 先把問題拆開

「同一個大腦」在實作上不是一個是非題，而是三個獨立維度：

| 維度 | 問題 | 影響 |
|---|---|---|
| 模型 | 四個 agent 是不是同一個 model id？ | 成本、延遲、偏誤多樣性 |
| 提示詞 | 角色差異寫在同一份 prompt，還是分開？ | 角色隔離程度、和稀泥風險 |
| 溫度 | 抽取與判斷用同一個 temperature 嗎？ | 抽取要穩定（0），判斷要一點彈性 |

A5 特別的地方：它是**唯一面向用戶的角色**，所以它的大腦選擇直接決定使用者看到什麼、
以及事後能不能解釋。A3 下單、A4 風控可以容忍的偏誤，A5 不能。

---

## 2. 四種可跑的拓撲

```
rule    感知層 ─┐
        指揮層 ─┴─▶ 規則引擎（無模型）

shared  A1 ─┐
        A2 ─┼─▶ 同一個 model、同一個溫度
        A5 ─┘

lens    A1 ─┐ T=0.0  抽取
        A2 ─┼─▶ 同一個 model
        A5 ─┘ T=0.2  判斷

split   A1 ─┐ 快模型  T=0.0
        A2 ─┼─▶ 感知層
        A5 ─┘ 強模型  T=0.2
        A4 ──▶ 只准規則（不配大腦）
```

| | `rule` | `shared` | `lens`（預設） | `split` |
|---|---|---|---|---|
| 成本 | 0 | 低 | 低 | 中 |
| 一致性 | 最高 | 高 | 高 | 中（要對齊格式） |
| 同源偏誤 | 無（但也無理解力） | 高 | 高 | 低 |
| 可重現 | 完全 | 好 | **最好**（單一模型版本） | 較差（多個版本） |
| 延遲 | 毫秒 | 低 | 低 | 中高 |
| 適合階段 | 離線、降級 | 打通鏈路 | **本專案** | A3/A4 接入後 |

---

## 3. 成本怎麼算（不是拍腦袋）

一次晨報的呼叫次數：

- `shared` / `lens`：**1 次**（A1、A2 的原始卡片由各自的服務產生，A5 只做一次匯總判斷）
- `split`：**1 次**（A5 判斷層）＋ 若同時重跑感知層抽取，再多 1–2 次
- `rule`：0

在 200 個訂閱者、每人每天 1 份晨報 + 平均 3 次追問的假設下，
`lens` 與 `shared` 的呼叫次數相同，差別只在「溫度與視角」——也就是**成本完全一樣**。

也就是說：`shared → lens` 是**免費升級**，沒有任何理由不做。
真正的成本分水嶺在 `lens → split`：多一次感知層呼叫，換取降低同源偏誤。
在 A3/A4 還沒接入、輸出還只是「建議」的階段，這個交換不划算。

> 建議在報告裡就照這個邏輯寫：**「我們的預設不是選了最便宜的，而是選了唯一一個成本不變、
> 但審計性更好的選項；split 保留為一個環境變數，等 A3/A4 上線再開。」**

---

## 4. 為什麼不選 `split`（現階段）

1. **可重播性**：proposal §3.4 要求「重播這個決策」。`lens` 只有一個模型版本要記錄；
   `split` 要記錄兩三個，任何一個版本漂移，歷史決策就不可比。
2. **格式對齊成本**：兩個模型對 JSON schema 的遵守程度不同，A5 要多一層修復邏輯，
   而這層修復本身會引入新的不確定性。
3. **邊際收益低**：目前的瓶頸不是「模型不夠多樣」，而是「新聞來源太少、A2 政策面還不穩定」。
   在輸入端解決問題，比在模型端堆多樣性有效。

## 5. 為什麼不選 `shared`

`shared` 讓抽取與判斷共用同一個溫度。抽取任務要的是穩定（T=0），判斷任務要的是一點權衡空間（T=0.2）。
把兩者壓成同一個值，等於牺牲其中一邊：要麼標籤不穩定，要麼判斷太死板。
`lens` 用同一個模型、兩個溫度，成本不變，這兩件事就分開了。

## 6. 什麼時候應該換成 `split`

出現以下任一情況，就把 `PQ_BRAIN_TOPOLOGY=split`：

- A3 開始產生真實的執行意圖，錯誤成本從「看到錯的建議」變成「下錯單」。
- A4 上線，需要一個**與判斷層不同來源**的風險視角（避免 A5 與 A4 一起錯）。
- 觀測到 A5 的錯誤與 A1 的錯誤高度相關（同源偏誤的實證）。

對照實驗怎麼做（有 API key 時介面上可直接跑）：

1. 固定同一份輸入（用 `replay` 的輸入快照）。
2. 分別用 `lens` 與 `split` 各跑 5 次。
3. 比較：置信度分佈、引用數、分歧數、延遲、tokens、以及「人類評審認為可用的比例」。
4. 若 `split` 在「可用比例」上沒有顯著提升，就維持 `lens`。

---

## 7. 一句話總結

> **同一個大腦，不同視角；把「不同大腦」留作一個可切換的實驗選項，而不是預設架構。**
> 因為 A5 賣的是可解釋的判斷，不是模型的多樣性。
